# 周边去哪儿（高德地点推荐）

一次任务只做一件事：**从同一个起点出发，给出最多 3 个真实、可步行到达的地点备选**，每个都附高德返回的步行距离与耗时。

## 什么时候用

- 用户问"附近有什么…""推荐几家…""步行 15 分钟内能到的…"，起点是坐标、地铁站、商场或地址。
- 只做单点周边的独立备选推荐。多站行程串联、驾车/公交方案、跨城出行不属于本 Skill。

## 一、先解析需求（不要跳过）

从用户一句话里抽取下表 6 项，缺的按缺省值补：

| 要素 | 取法 | 缺省 |
| --- | --- | --- |
| 城市 | 用户明确说的城市 | 以起点坐标所在城市为准 |
| 起点 | 优先用给定坐标；给的是地名时先做地理编码 | 没有起点就先问一次 |
| 地点类型 | "咖啡""餐厅""公园"等具体类型词 | 无 |
| 步行时间上限 | "步行不超过 15 分钟"→15 分钟 | 不限，但仍要报步行时间 |
| 推荐数量 | "最多 3 家"→3 | 3 |
| 偏好 | 近 / 评分高 / 安静 / 适合办公 | 按步行距离升序 |

**明确条件（数量、步行时间上限、类型）是硬约束，任何情况下不能突破。** 模糊偏好（安静、人少、环境好）只影响排序和措辞，不能变成"事实"。

## 二、查地点：工具调用顺序

高德 MCP 常见工具：`maps_geo`（地址→坐标）、`maps_around_search`（周边搜）、`maps_text_search`（关键字搜）、`maps_search_detail`（POI 详情，含坐标）、`maps_direction_walking`（步行路线）。名称以当前环境实际提供的为准——周边搜也可能叫 `maps_search_around`，按能力对应即可。

1. **确定起点坐标**
   - 用户已给"经度,纬度"→ 直接用，不要重新编码。
   - 只给地名、地铁站、商场、地址 → `maps_geo(address, city)`，坐标在 `return[0].location`（不是 `geocodes`）。统一成"经度,纬度"。
   - 编码失败或结果为空：请用户补充更具体的起点；若必须继续，用用户给的区域中心并明确写"起点为近似位置"。

2. **周边搜索**
   - 调 `maps_around_search(location=起点坐标, radius=半径, keywords=类型词)`。`keywords` 传"咖啡""餐厅""公园"这类具体类型词；半径是字符串。
   - 半径按下式估算：用户给了步行时间上限 T 分钟时，`radius ≈ T × 80` 米（15 分钟 ≈ 1200 米），最小 500、最大 3000。
   - 结果为空或明显偏少：半径放宽到 1.5 倍再搜一次，同一次任务最多放宽两次；仍为空就进入"无结果"处理。
   - **这个接口通常只返回 `id` / `name` / `address` / `typecode` / `photos`，既没有坐标也没有距离**，别指望它给距离。
   - 类型词不理想时可退一步用 `maps_text_search(keywords, city)`，但结果同样要以起点为圆心重新筛。

3. **取候选坐标并预筛**
   - 搜索返回里带 `location` 就直接用；没有就对该候选调 `maps_search_detail(id)` 取 `location`（顺带可能拿到 `biz_ext` 里的评分、营业时间）。
   - 候选控制在 **5–6 个**：先按名称、`typecode`、地址剔除明显不符类别（搜咖啡返回银行/加油站）或明显跨片区的，再按搜索返回顺序取。每个候选要 2 次调用，别一次拉 10 个。
   - `detail` 也拿不到坐标的候选直接剔除，并记下剔除了几个。

4. **步行路线**（逐个查，不能用直线距离替代）
   - 调 `maps_direction_walking(origin=起点坐标, destination=候选坐标)`；距离和耗时在 `route.paths[0].distance`（米）与 `route.paths[0].duration`（秒）里。字段常是字符串，先转成数字；多段时取 `paths` 里的总路径，不要自己把 `steps` 加起来。
   - 秒 ÷ 60 向上取整，报"约 X 分钟"。**不要**用 `maps_bicycling`、`maps_direction_driving` 或 `maps_distance` 的数字冒充步行距离。
   - 串行调用、两次之间留约 1 秒：接口有 QPS 限制，连续快速请求会返回空 `paths`——那不是"没有路"，是被限流；先退避 1–2 秒重试，最多 2 次，仍失败就只查最近的 4–5 个，并在回答里说明"部分候选未取得步行路线"。
   - 每个候选都从**同一起点独立**计算，不要串成"先去 A 再去 B"。

5. **筛选与排序**
   - 硬筛选：步行耗时 ≤ 用户上限的候选才保留。
   - 排序：用户说"优先近一点/方便一点"→ 按步行距离升序（距离相同再看耗时）；用户说"评分高"→ 按返回的评分降序并在理由里带上评分，返回里没有评分就说明"接口未返回评分"、改按步行距离排序；无偏好时同样按步行距离升序。
   - 取前 N 个，N = 用户要的数量，**最多 3 个**。
   - 超出时间上限但用户可能感兴趣的候选，只能单独提一句"另有 X 步行约 Y 分钟，超出限制"，**不能混进推荐列表**。

调用示例（数值仅示意格式，实际以工具返回为准）：

```
maps_geo(address="龙翔桥地铁站", city="杭州")      → return[0].location "120.166,30.2524"
maps_around_search(location="120.166,30.2524", radius="1200", keywords="咖啡")
                                                   → pois[0].id "B0IARZXFJB"（无坐标）
maps_search_detail(id="B0IARZXFJB")                → location "120.166863,30.252275"
maps_direction_walking(origin="120.166,30.2524", destination="120.166863,30.252275")
                                                   → route.paths[0].distance 199, .duration 159
```

一次完整任务大约 1 次地理编码 + 1–3 次周边搜 + 5–6 次详情 + 5–6 次步行路线，留好间隔，20–30 秒可以跑完。

## 三、回答格式

先一句话给结论，再给表格，最后 1–2 句补充：

| # | 地点 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- | --- |
| 1 | XX咖啡（XX店） | XX市XX区XX路XX号 | 420 米 | 约 6 分钟 | 步行最短，出站即到，适合快速解决一杯 |

- 名称、地址照抄高德返回，不改写、不补全门牌号；地址里自带的"步行 440 米"这类备注不是路线数据，别拿它当步行距离。
- 步行距离和时间来自路线查询，保留"约"字，单位用米 / 分钟。
- 推荐理由一句话，只引用已取得的数据（距离、时间、类别、评分、营业时间）；没有数据支撑的感受性描述一律标"未核实"。
- 表格后用一句话收口：覆盖范围（"3 家都在 12 分钟步行圈内"）或不足说明。
- 用用户的语言回答；用户说中文就用中文。

## 四、不足、异常与信息缺失（必须如实说）

- **区分"没结果"和"出错"**：返回里 `pois` 是空数组 = 这个范围内确实没有；返回 `xxx failed: ...` 或 `isError` = 接口报错（Key、权限、限流、参数），必须如实报错，不能写成"附近没有"。
- **结果不够**：符合条件只有 k 家（k 小于用户要的数量）时，推荐这 k 家，并说明"周边 X 米 / 步行 X 分钟内符合条件的只有 k 家"，再给放宽建议（扩大半径、放宽到 20 分钟、换类型）。
- **完全没有结果**：直接说"在 X 米范围内没有找到符合条件的<类型>"，写清实际用过的关键词和半径，给放宽建议。不要为凑数编地点。
- **工具失败或超时**：同一调用最多重试一次；仍失败就说明哪一步失败（周边搜索 / 详情 / 步行路线）和"本次没有拿到可靠的步行数据"。已确认的地点可以列出，但必须标注缺路线数据的那几家。
- **信息缺失**：营业状态、排队情况、安静程度、是否适合办公、是否宠物友好等，没有工具依据就写"未核实"，不要推测。
- **绝对不能**：编造 POI、地址、评分、距离或耗时；用直线距离冒充步行距离；拿骑行/驾车路线顶替步行路线；把超时地点写成"符合条件"；承诺"一定营业""不用排队"。

## 五、提交前自检

- [ ] 数量 ≤ 用户要求，且 ≤ 3
- [ ] 每条都有名称、地址、步行距离、步行时间、一句理由
- [ ] 所有步行数据来自 `maps_direction_walking` 的 `route.paths[0]`，且都不超过用户的时间上限
- [ ] 排序与用户偏好一致（说"优先近"就按步行距离升序）
- [ ] 结果不足、查询失败、未核实的地方都写了说明，没有任何编造
