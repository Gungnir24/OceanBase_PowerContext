# Agent 长期记忆的写入、检索与遗忘：一个可审计的上下文服务设计

> 本文为参赛示例数据，内容为虚构，仅用于演示“记忆”相关检索。

## 摘要

多轮 Agent 的失败往往不是模型能力不足，而是上下文管理失当：该记住的偏好没有留下，该遗忘的临时信息却反复出现。本文把 Agent 记忆拆成三层：证据（Source）、长期事实（Memory）与一次性上下文（Prepared Context），并给出一个可审计的服务设计。

## 三层结构

证据层保存原始交互，写入后不可变；长期事实层保存经过确认的偏好、约束、决策与进展，支持版本与停用；一次性上下文层在每次模型调用前，按当前问题做有界召回，并受字节预算约束。三层分离的好处是：模型可以提出候选记忆，但只有应用或用户确认后才进入长期层，避免把模型幻觉固化成“事实”。

## 写入与检索

写入采用“显式保存”策略：当用户说“记住……”或点击保存时，才写入长期记忆；普通对话只进入证据层。检索时先按问题做关键词与语义混合召回，再按类别（偏好、约束、决策、进展）分配名额，防止某一类记忆挤占全部预算。

我们在 80 个跨会话任务上做了对照：没有记忆时，用户平均需要重复 2.3 次背景信息；启用记忆后下降到 0.4 次。记忆条目的平均长度为 42 字，过长的记忆会被截断或拆分，因为长文本在召回时更容易误命中。

## 遗忘与审计

记忆不是越多越好。过期进展、被推翻的决策、一次性口令都应停用而不是删除，以保留审计轨迹。停用后的条目不再参与召回，但仍可通过历史版本追溯。我们建议为每条记忆记录来源与原因，这样当用户质疑“你为什么记得这个”时，系统能给出证据。

## 局限

本文的评测规模较小，且记忆抽取仍依赖人工确认。自动抽取如何与人工审核结合、如何评估“记忆质量”而不是“记忆数量”，仍是开放问题。
