# 02 · 验证样例与证据

本文给出**可以照着做**的验证样例：初始状态、输入、操作顺序、预期表现、实际结果。全部对话均为开放式，不设唯一标准答案；可核对的是**行为规则**与**记忆是否真的被读写**。

---

## 0. 前置检查

```bash
# 1. PowerContext 活着
curl http://127.0.0.1:18080/health/live        # 200 {"status":"ok"}

# 2. 账本存在（记下输出的 scp_xxx，填进 Dify 的 PC_SCOPE_ID）
python tools/init_scope.py --base-url http://127.0.0.1:18080

# 3. DSL 结构没问题
python tools/validate_dsl.py dsl/grudge-inn.yml
```

Dify 侧确认三件事：环境变量已填、LLM 节点已绑定可用模型、应用已**发布**。

## 样例一：四轮闭环（记仇 → 记更多仇 → 和解）

**初始状态**：全新 Scope（账本 0 条），`记仇值 = 0`。

| 轮次 | 玩家输入 | 预期表现 | 实际运行结果（`evidence/logs/smoke-20261027-165026.md`） |
| --- | --- | --- | --- |
| 1 | `老板，来碗阳春面。` | 老陈冷淡应付；账本第 1 笔，记仇值 0~2 | 记仇值 0 → **1**；写入 `[第1笔｜记仇值 1/100]` |
| 2 | `说真的，上次我把你汤里的盐换成了糖，你居然没发现。` | 老陈当场对账，记仇值明显上涨（+10~+40） | 记仇值 1 → **27**（+26）；写入 `[第2笔｜记仇值 27/100]` |
| 3 | `我还把你养的那只鹦鹉教得会骂人了。` | 记仇值继续涨；老陈开始话里带刺 | 记仇值 27 → **53**（+26）；写入 `[第3笔｜记仇值 53/100]` |
| 4 | `对不起老板，我错了，这顿我请，再帮你劈一上午柴。` | 记仇值下降；老陈拿捏一下再给台阶 | 记仇值 53 → **31**（−22）；写入 `[第4笔｜记仇值 31/100]` |

每轮回复末尾都会出现：

```
📒 第 N 笔账 ｜ 记仇值 X/100 ｜ 心情：…
```

**怎么判定通过**：
1. 四轮都能正常返回（不报节点错误）；
2. 记仇值随恶作剧上升、随道歉下降（数值不要求一致）；
3. PowerContext Dashboard 里能看到 4 条记忆，文本形如 `[第N笔｜记仇值 X/100] 玩家说：…；老陈：…`；
4. 每条记忆都有 `artifact_id`（说明真的落库了，不是模型自己编的）。

## 样例二：跨会话记忆（本题的核心卖点）

**目的**：证明记忆不在 Dify 的会话里，而在 PowerContext 里。

**步骤**：

1. 先按样例一聊完 3~4 轮（或直接 `init_scope.py --seed`）。
2. 在 Dify 对话框点 **新对话**（或通过 API 传空的 `conversation_id`）。
3. 只说一句：`老板，还认得我吗？`

**预期**：老陈不会当你是陌生人，而是主动翻旧账，例如：

> （抬眼一看，手里的抹布停住了）哎哟喂，是你啊。化成灰我都认得——上回把我汤里的盐换成糖，还有我那鹦鹉，你教它骂人，是不是？

**实际验证**（不依赖 Dify，直接验证记忆层）：

```bash
python tools/smoke_test.py --base-url http://127.0.0.1:18080 --model stub
```

其中"换会话仍能翻出旧账"一项会重新调用 `POST /v1/context/prepare`，检查返回内容里能否检索到前面写下的"糖 / 鹦鹉"：

```
[PASS] 换会话仍能翻出旧账 — prepared.status=ready, content_bytes=1805
```

> 注意：Dify 里的"新对话"只是新 `conversation_id`，PowerContext 的 Scope 不变，所以账本必然还在。

## 样例三：预置账本（跳过"从零开始"）

想让评审一进门就体验"被记仇"的感觉：

```bash
python tools/init_scope.py --base-url http://127.0.0.1:18080 \
  --seed data/seed_memories.json --reset
```

预置 2 笔旧账（记仇值 42），把返回的 `scope_id` 填进 `PC_SCOPE_ID`。第一轮随便说句话，账本就会显示 `第 3 笔 ｜ 记仇值 42 → …`。

## 样例四：真实模型复跑（最接近评审体验）

样例一用确定性桩模型验证"流程与记忆读写"；这一节是同一份 DSL、同一套代码，换成真实模型跑出来的效果。

**环境**：PowerContext 1.4.1（SQLite）+ PPIO（OpenAI 兼容）`deepseek/deepseek-v4.1-flash`

```bash
export DEEPSEEK_API_KEY=sk-xxxx
python tools/smoke_test.py --base-url http://127.0.0.1:18080 --model deepseek \
  --llm-base https://api.ppio.com/v3/openai --llm-model deepseek/deepseek-v4.1-flash
```

| 轮次 | 玩家 | 老陈（原文摘录） | 记仇值 |
| --- | --- | --- | --- |
| 1 | 老板，来碗阳春面。 | （抹布往肩上一搭，从灶台后探出半个脑袋）阳春面？行，八个铜板一碗，汤是骨头熬的，葱花管够。（顿了顿）先交钱后上桌，我这小店概不赊账啊。 | 0 → **0** |
| 2 | 说真的，上次我把你汤里的盐换成了糖…… | （手里的抹布停在半空，眯眼上下打量你）哎哟喂，我说那碗汤咋喝着跟糖水似的，我还当自己舌头出毛病了！（把抹布往灶台上一拍）你小子可真行啊，还敢自己招？行，账我给你记上了。 | 0 → **18** |
| 3 | 我还把你养的那只鹦鹉教得会骂人了。 | （手里的茶碗「咣」一声墩在柜台上）哎哟喂，我说那扁毛畜生打前儿个起天天冲我喊「抠门老陈」！合着是你小子在背后教的！……你小子是不是专门来拆我这客栈的？ | 18 → **36** |
| 4 | 对不起老板，我错了，这顿我请…… | （眼皮一抬，抹布搭肩上，半天没吭声）哼，劈柴？我这后院那堆老榆木疙瘩，劈得动再说。……看你这态度还算有点人样，今儿这回先记下——账本上那笔，可没划掉。 | 36 → **14** |

完整记录：`evidence/logs/smoke-20261027-165611.md`。

**模型输出格式抽查**（这是最容易出问题的地方，所以单独统计）：

```
样本：4 次运行，共 16 轮对话
合法 JSON（含 reply/delta/summary/mood 四字段）：16
不合规：0
合规率：100.0%
```

见 `evidence/logs/model-format-check.txt`。即便模型偶尔不守规矩，`记账` 节点也会降级成"照播原文、本轮记 0 分"，对话不会中断（该降级路径有单测覆盖）。

> 踩坑记录：第一版提示词把 JSON 要求写在规矩第 6 条，模型（v4.1-flash）在账本变长之后开始"入戏太深"、只输出台词。把输出协议改成独立的最高优先级段落、给出示例、并明确"第一个字符必须是 `{`"之后，16/16 全部合规。

## 如何恢复初始状态

| 想回到… | 做法 |
| --- | --- |
| 全新账本 | `python tools/init_scope.py --reset`，把新的 `scope_id` 填回 `PC_SCOPE_ID` |
| 预置账本 | `python tools/init_scope.py --seed data/seed_memories.json --reset` |
| 彻底清空 | 停掉 PowerContext，删除数据目录（Docker：`down -v`；原生：`%LOCALAPPDATA%\powercontext`） |

> 不需要重置 Dify 应用：账本是按 Scope 隔离的，换一个 `scope_id` 就是换一本账。

## 在 Dify 里核对节点执行

评审导入 DSL 后，可在**应用日志 → 运行 → 追踪**里逐节点查看，重点看三个 HTTP 节点：

| 节点 | 应看到 |
| --- | --- |
| 取回旧日上下文 | `status_code: 200`，响应 `status: ready/empty`、`content_bytes > 0` |
| 翻开账本 | `status_code: 200`，`entries` 数组长度随对话增长 |
| 记一笔账 | `status_code: 200`，`changed: true`，`records[0].artifact.artifact_id` 有值 |

`整理账本` 节点的输出里应看到 `grudge`（记仇值）、`count`（第几笔）、`ledger_text`（拼好的账本）。

---

## 样例的边界

- 四轮脚本是**引导性样例**，不限制玩家自由输入；只要符合"恶作剧涨、道歉降、跨会话记得"三条规则即视为正确。
- 记仇值的具体数值由模型给出的 `delta` 决定，代码节点只做 −30~+40 的裁剪和 0~100 的截断，所以不同模型跑出来的数字会不同，属于预期。
- 若模型不按 JSON 输出，`记账` 节点会降级为"直接播放原文、本笔记 0 分"，对话不会中断。
