# 01 · 部署与运行

本文从一台干净机器开始，把《记仇客栈》跑起来。全程约 10~15 分钟（不含拉镜像）。

---

## 0. 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Dify | **1.17.x / 1.18.x**（DSL `version: 0.7.0`） | 官方 docker compose 部署即可，需包含 `api`、`worker`、`web`、`sandbox`、`plugin_daemon` |
| PowerContext | **1.4.1** | PyPI 包 `powercontext[cli,server]`，Python 3.11+ |
| 模型 | 任意支持对话的模型 | 推荐 DeepSeek `deepseek-chat`；通义千问 `qwen-plus`、GPT 等均可 |
| 网络 | Dify 容器 → PowerContext 可达 | 同一台机器时用 `host.docker.internal` |
| 本地自测（可选） | Python 3.11+、`pip install pyyaml` | 跑 `tools/` 下的脚本 |

> 本作品**不需要** Embedding 模型、不需要 Rerank、不需要知识库。

---

## 1. 启动 PowerContext Server

### 方式 A：Docker（推荐）

```bash
cd dify
docker compose -f docker/docker-compose.powercontext.yml up -d
```

等健康检查通过（首次要装依赖，约 1~3 分钟）：

```bash
curl http://127.0.0.1:18080/health/live     # 期望 200
curl http://127.0.0.1:18080/health/ready    # 期望 200，body 里 database=ready
```

Dashboard（可选，方便看账本）：<http://127.0.0.1:18080/dashboard/home>

### 方式 B：原生安装（Windows 推荐）

```powershell
py -3.12 -m venv .venv
.venv\Scripts\pip install "powercontext[cli,server]==1.4.1"

# powercontext.env
@"
POWERCONTEXT_SERVER_HTTP_HOST=127.0.0.1
POWERCONTEXT_SERVER_HTTP_PORT=18080
POWERCONTEXT_SERVER_DASHBOARD_ENABLED=true
POWERCONTEXT_SERVER_ACCESS_MODE=disabled
"@ | Out-File -Encoding utf8 powercontext.env

.venv\Scripts\powercontext config validate --env-file powercontext.env
.venv\Scripts\powercontext server run --env-file powercontext.env
```

看到 `Uvicorn running on http://127.0.0.1:18080` 即成功。数据默认落在 `%LOCALAPPDATA%\powercontext` 下的 SQLite 文件，重启不丢。

### 方式 C：用已有的远程 PowerContext

把 `PC_BASE_URL` 指向对方地址即可。若对方开启了鉴权（`ACCESS_MODE=enforced`），见第 5.3 节。

## 2. 建账本（Scope）

```bash
python tools/init_scope.py --base-url http://127.0.0.1:18080
```

输出：

```
scope_id: scp_xxxxxxxxxxxxxxxxxxxx
```

- `scope_id` 是**一家客栈的账本编号**，所有记忆都写在这个 Scope 下。
- 想直接体验"老账本"，加 `--seed data/seed_memories.json`（会预置 2 笔旧账，记仇值 42）。
- 想清空重来，加 `--reset`（会新建一个 Scope；旧账本仍在，只是不再被使用）。

> 说明：`--reset` 不复用旧 idempotency key，是**新建**而非删除。PowerContext 1.4.1 没有"删除 Scope"的公开接口，这是有意的设计。

## 3. 导入 Dify DSL

1. 打开 Dify → **工作室** → **创建空白应用** → 右上角 **导入 DSL 文件**。
2. 选择 `dify/dsl/grudge-inn.yml`。
3. 若提示 DSL 版本与当前 Dify 不完全一致，选择**继续导入**（结构基于 1.18 导出格式，1.17 亦可读）。

导入后应看到 8 个节点、7 条连线：

```
开始 → 取回旧日上下文 → 翻开账本 → 整理账本 → 老陈 → 记账 → 记一笔账 → 回答
```

---

## 4. 绑定模型

打开 **LLM 节点「老陈」**，在右侧把模型换成你工作区里可用的对话模型：

| 服务商 | 推荐模型 | 备注 |
| --- | --- | --- |
| DeepSeek 官方 | `deepseek-chat` | DSL 默认值 |
| **PPIO（派欧云）** | `deepseek/deepseek-v4.1-flash` | **本作品实测所用**，OpenAI 兼容，见 4.1 |
| 阿里云百炼 | `qwen-plus` | 需在 Dify 装 Tongyi 插件 |
| OpenAI | `gpt-4o-mini` | 需能访问外网 |

保留节点的 `temperature: 0.9`，温度高一点老陈才够"活"。

> 模型名必须在你自己的 Dify 里存在，否则运行时会报 "model not found"。这是导入 DSL 后**唯一必须手动改**的地方。

### 4.1 用 PPIO 接入（本作品的实测环境）

PPIO 提供 OpenAI 兼容接口，不需要单独插件，用 Dify 官方的 **OpenAI-API-compatible** 插件即可：

| 配置项 | 值 |
| --- | --- |
| API Base URL | `https://api.ppio.com/v3/openai` |
| API Key | 你的 PPIO Key（`sk-...`） |
| 模型名称 | `deepseek/deepseek-v4.1-flash`（实测 16/16 轮 JSON 合规）；也可填 `deepseek/deepseek-v4-pro` |
| 模型类型 | LLM（对话） |

步骤：**设置 → 模型供应商 → 安装 OpenAI-API-compatible 插件 → 添加模型**，按上表填写 Base URL 与模型名，保存后回到 LLM 节点选中它。

> 想先用命令行验证这套配置能不能通（不经过 Dify）：
>
> ```bash
> export DEEPSEEK_API_KEY=sk-xxxx
> python tools/smoke_test.py --base-url http://127.0.0.1:18080 --model deepseek \
>   --llm-base https://api.ppio.com/v3/openai --llm-model deepseek/deepseek-v4.1-flash
> ```

## 5. 配置环境变量

应用编辑器右上角 **…** → **环境变量**（或左侧「变量」面板）：

| 变量 | 必填 | 示例值 | 说明 |
| --- | --- | --- | --- |
| `PC_BASE_URL` | ✅ | `http://host.docker.internal:18080` | Dify 在容器里 → 宿主机用 `host.docker.internal`；Dify 与 PowerContext 同机原生 → `http://127.0.0.1:18080` |
| `PC_SCOPE_ID` | ✅ | `scp_xxxxxxxx` | 第 2 步的输出 |
| `PC_TOKEN` | ❌ | 空 | 仅当 PowerContext 开启鉴权时使用，见 5.3 |

### 5.1 `host.docker.internal` 不通怎么办

Linux 上 Docker 默认没有这个域名，二选一：

```yaml
# 在 Dify 的 docker-compose.yaml 里给 api / worker 加：
extra_hosts:
  - "host.docker.internal:host-gateway"
```

或直接把 `PC_BASE_URL` 写成宿主机在 docker 网桥上的 IP（通常是 `172.17.0.1`），并让 PowerContext 监听 `0.0.0.0`。

### 5.2 Dify 的 SSRF 白名单（本地部署最常踩的坑）

Dify 的 HTTP 请求节点默认**禁止访问内网地址**（含 `host.docker.internal`、`172.x`、`192.168.x`、`127.0.0.1`）。
不放开这条，第一次对话就会失败，报：

```text
Run failed: Access to 'http://host.docker.internal:18080/v1/context/prepare'
was blocked by SSRF protection (e.g. SSRF_PROXY_ALLOW_PRIVATE_IPS=172.21.0.0/16 ...)
```

处理办法：把 PowerContext 所在的网段加进 Dify 的 `docker/.env`，然后重建 `ssrf_proxy` 和 `api`：

```bash
# docker/.env
SSRF_PROXY_ALLOW_PRIVATE_IPS=192.168.65.0/24   # Docker Desktop(Windows/macOS) 的宿主网关网段
# SSRF_PROXY_ALLOW_PRIVATE_IPS=172.17.0.0/16   # Linux 上的 docker0 网桥
```

```bash
docker compose up -d ssrf_proxy api worker
```

网段怎么确认：

```bash
docker exec docker-api-1 python -c "import socket;print(socket.gethostbyname('host.docker.internal'))"
# 192.168.65.254 → 网段就是 192.168.65.0/24
```

`ssrf_proxy` 容器会把它渲染成 `/etc/squid/dify_allow_private.conf`，可以用这条命令确认生效：

```bash
docker exec docker-ssrf_proxy-1 cat /etc/squid/dify_allow_private.conf
```

> 只放行你实际用到的网段。PowerContext 部署在公网域名或 Dify 同 compose 网络里时，通常不需要改这里。

### 5.3 验证连通性

在 Dify 容器内执行：

```bash
docker exec -it docker-api-1 sh -lc "wget -qO- http://host.docker.internal:18080/health/live"
```

返回 `{"status":"ok",...}` 即通。

### 5.4 开启鉴权的写法

如果 PowerContext 用 `POWERCONTEXT_SERVER_ACCESS_MODE=enforced` + `POWERCONTEXT_SERVER_AUTH_TOKEN=xxx` 启动：

1. 环境变量 `PC_TOKEN` 填该 token；
2. 把三个 HTTP 节点（取回旧日上下文 / 翻开账本 / 记一笔账）的**鉴权**从「无」改成 **API Key → Bearer**，值填 `{{#env.PC_TOKEN#}}`。

> 注意：Dify 的 API Key 鉴权在渲染后为空时会直接报错，所以默认 DSL 用的是「无鉴权」，只在需要时才改。

## 6. 发布与入口

点 **发布** → **更新**，然后在「工作室」点开应用，或在「访问 API」页面拿到 API 入口。

- **Web 入口**：应用预览页的对话框，直接聊天即可。
- **API 入口**：`POST /v1/chat-messages`（Chatflow 走 `advanced-chat` 接口），`conversation_id` 传空则新建会话——正好用来验证"跨会话记忆"。

```bash
curl -X POST "http://<dify>/v1/chat-messages" \
  -H "Authorization: Bearer app-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"inputs":{},"query":"老板，上次那把盐的事你还记得吗？","response_mode":"blocking","user":"judge-001"}'
```

## 7. 本地自测（不依赖 Dify）

这两步用来证明"DSL 里的代码 + PowerContext 的记忆闭环"本身是通的，排错时先跑它们。

```bash
pip install pyyaml

# 1) DSL 静态校验：节点字段、连线、变量引用、模式约束
python tools/validate_dsl.py dsl/grudge-inn.yml

# 2) 两段 Code 节点的单元测试（不需要任何服务）：53 项边界用例
python tools/test_code_nodes.py

# 3) 端到端：用 DSL 里真实的 Code 节点代码 + 真实 PowerContext API 跑四轮对话
python tools/smoke_test.py --base-url http://127.0.0.1:18080 --model stub
```

`smoke_test.py` 会断言：账本从空开始 → 每轮都写入 → 恶作剧让记仇值上升 → 道歉让记仇值下降 → 换会话仍能翻出旧账，并把全过程写进 `evidence/logs/`。

想用真实模型跑（输出更像人）：

```bash
export DEEPSEEK_API_KEY=sk-xxx
python tools/smoke_test.py --base-url http://127.0.0.1:18080 --model deepseek
```

### 7.1 在真实 Dify 上复跑（可选，最接近评审视角）

`tools/dify_live_test.py` 会自己走一遍 Dify 的导入、绑模型、发布、建 API Key、跑 5 轮对话，
并把台词、节点轨迹、PowerContext 账本一起写成证据文件：

```bash
python tools/dify_live_test.py \
  --password '<你的 Dify 管理员密码>' \
  --scope scp_xxxxxxxx \
  --model deepseek/deepseek-v4.1-flash \
  --provider langgenius/openai_api_compatible/openai_api_compatible
```

默认输出到 `evidence/dify-live-<时间戳>.md|json`；退出码 0 表示 5 轮全部跑通、且每轮只有一条账本行。

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 节点报 404 | `PC_BASE_URL` 末尾多了 `/`，拼成 `//v1/...` | **地址不要以 `/` 结尾**，写成 `http://host.docker.internal:18080` |
| 节点报 `HTTP request failed` / 连接超时 | Dify 容器访问不到宿主机 | 检查 `PC_BASE_URL`、`host.docker.internal`、PowerContext 是否 `0.0.0.0` 监听 |
| 报 `was blocked by SSRF protection` | Dify 默认禁止 HTTP 节点访问内网 | 见 5.2，把网段加进 `SSRF_PROXY_ALLOW_PRIVATE_IPS` 后重建 `ssrf_proxy` |
| 422 `scope_id` 校验失败 | `PC_SCOPE_ID` 为空或写错 | 重新跑 `init_scope.py`，把 `scp_xxx` 填进去 |
| 模型输出不是 JSON，老陈说话很怪 | 模型不听话 | `code_parse` 有兜底（按关键词估 delta），不会崩也不会重复账本行；想更稳可换 `deepseek-v4-pro` |
| 回答末尾出现两条「📒 第 N 笔账」 | 模型自己在台词里补了一条账本行 | `code_parse` 会削掉；若还出现，说明导入的是旧版 DSL |
| Code 节点报 `sandbox` 相关错误 | Dify 缺 `sandbox` 服务 | 用官方 `docker-compose.yaml`，别裁剪 `sandbox` |
| 老陈不记得上一轮 | 账本没写进去 | 看 PowerContext Dashboard 是否有条目；看 `记一笔账` 节点的响应 |
| 记仇值不动 | LLM 没按 JSON 输出且没命中关键词兜底 | 看节点输出里的 `delta`；必要时降 temperature 到 0.6 |
| 每一轮都收到两条一样的用户消息 | 自定义 DSL 时把 `{{#sys.query#}}` 同时写进了 prompt_template 和 memory | 见 03 文档「为什么 prompt 里只有 system」 |

## 9. 卸载 / 重置

```bash
# 停服务（Docker）
docker compose -f docker/docker-compose.powercontext.yml down

# 连数据一起删
docker compose -f docker/docker-compose.powercontext.yml down -v
```

原生安装：停掉 `powercontext server run`，删除 `%LOCALAPPDATA%\powercontext`（Windows）或 `~/.local/share/powercontext`（Linux）。
